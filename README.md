## 1. ファイルの場所

| 場所 | 中身 | ふだん触る? |
| --- | --- | --- |
| `works/` | **作品ファイル**(1作品=1ファイル) | ◎ よく触る |
| `settings/tags.txt` | **タグの名前と説明文** | ○ ときどき |
| `index.html` | ページの骨組み。案内・自己紹介・おすすめ・お知らせの文章 | ○ ときどき |
| `css/style.css` | デザイン(色はファイルの先頭にまとめてあります) | △ |
| `js/app.js` | プログラム | ✕ 触らなくてOK |
| `tools/build-index.js` | 作品一覧を自動で作るプログラム | ✕ |
| `.github/workflows/pages.yml` | 自動公開の設定 | ✕ |

### 書庫の一覧は「自動」で作られます

`works/` フォルダに作品ファイルを置くだけで、書庫の一覧に自動で追加されます。**一覧ファイルを手で書きかえる必要はありません。**

しくみ:GitHub に変更を保存するたびに、GitHub Actions(自動で動く仕組み)が `works/` の中のファイルを調べて、一覧(`works/index.json`)を作ってからサイトを公開します。作品の並び順は、作品ファイルに書いた「公開日」の新しい順です。

## 2. GitHub Pages で公開する(最初に1回だけ)

1. このサイトのファイルが **`main` ブランチ** に入っていることを確認します。
   (別のブランチにある場合は、GitHub の「Pull requests」から `main` にマージします)
2. GitHub のリポジトリのページで、上の **「Settings」** を開きます。
3. 左のメニューから **「Pages」** を開きます。
4. 「Build and deployment」の **「Source」** を **「GitHub Actions」** に変更します。
   (「Deploy from a branch」ではなく「GitHub Actions」を選ぶのがポイントです)
5. 上の **「Actions」** タブを開き、「サイトを公開」が緑のチェック ✅ になるまで、1〜2分待ちます。
   - まだ動いていない場合は、「サイトを公開」→「Run workflow」ボタンで手動で動かせます。
6. もう一度「Settings」→「Pages」を開くと、上のほうに公開されたURLが表示されます。
   ふつうは `https://ユーザー名.github.io/maaiika-bunko/` です。

> 💡 以後は、`main` ブランチのファイルを変更するたびに、自動で公開しなおされます(反映まで1〜2分)。
> 反映されないときは、ブラウザの再読みこみ(スマホなら少し待ってから開き直す)を試してください。

## 3. 作品の書き方(ひな形)

作品は、テキストファイル(`.txt`)または Markdown ファイル(`.md`)です。
下のひな形をコピーして使ってください。

```
作品名: ここに作品名
サブタイトル: ここにサブタイトル
作者名: 鬼巛
タグ: 童話、コメディ
内容: 書庫の一覧に出る、1行の紹介文。
公開日: 2026-10-01
---
　ここから本文です。

　空行を入れると、段落の区切りになります。
　ふつうの改行は、そのまま改行になります。
```

### 項目の説明

| 項目 | 必須? | 説明 |
| --- | --- | --- |
| `作品名:` | **必須** | 作品のタイトル |
| `サブタイトル:` | 省略可 | タイトルの下に小さく出ます |
| `作者名:` | 省略可 | 省略すると「鬼巛」になります |
| `タグ:` | 1〜2個 | 2個のときは読点「、」で区切ります。`settings/tags.txt` にあるタグ名と同じ字で書きます |
| `内容:` | 省略可 | 書庫やおすすめに出る1行の紹介文 |
| `公開日:` | 書いてください | `2026-10-01` の形。新しい順の並びと、「最初に開いたときに出る最新作品」の判定に使います |

- 項目の **順番は自由** です。使わない項目は、行ごと消してかまいません。
- コロンは半角「`:`」でも全角「`:`」でも読めます。
- 項目の下に、**`---` だけの行(水平線)を1行** 入れます。その下がすべて本文です。
- 本文は前置きなしで、そのまま作品ページに表示されます。

### 本文で使える書き方(おまけ)

- **ルビ(ふりがな)**:`|漢字《かんじ》` と書くと、漢字の上にふりがながつきます。
  漢字だけのときは `|` を省いて `漢字《かんじ》` でもOKです。
- 縦書きのとき、`12` のような2桁の半角数字や `!?` は、自動で横に並びます。

## 4. 作品を追加する

GitHub の Web 画面だけでできます。

1. GitHub のリポジトリのページで、**`works` フォルダ** を開きます。
2. 右上の **「Add file」→「Create new file」** を押します。
3. ファイル名を入れます。
   - **半角の英数字とハイフン** がおすすめです。例:`2026-10-15-tsuki-no-soda.md`
   - このファイル名(`.md` を除いた部分)が、作品のURLになります。
     例:`https://ユーザー名.github.io/maaiika-bunko/?work=2026-10-15-tsuki-no-soda`
   - 最後は必ず `.md` か `.txt` にします。
4. 本文の欄に、[ひな形](#3-作品の書き方ひな形) をコピーして貼りつけ、書きかえます。
5. 右上の **「Commit changes...」** を押し、出てきた画面でもう一度 **「Commit changes」** を押します。
6. 1〜2分で、サイトの書庫に自動で追加されます。

> 💡 **下書き**:ファイル名の先頭を `_`(アンダーバー)にすると(例:`_shitagaki.md`)、書庫には出ません。
> ただし、リポジトリが公開されている場合、ファイルそのものは誰でも見られる点に注意してください。

> 💡 パソコンにあるテキストファイルをそのまま入れたいときは、手順2で「Upload files」を選び、ファイルをドラッグして入れます。文字コードは UTF-8 にしてください。

## 5. 作品を差し替える・削除する

### 差し替える(仮の作品を自分の原稿にするときも、これ)

1. `works` フォルダで、差し替えたい作品ファイルを開きます。
2. 右上の **鉛筆マーク(Edit this file)** を押します。
3. 中身を書きかえて、**「Commit changes...」→「Commit changes」** を押します。

> 仮の作品(5本)は、次のファイルです。中身をまるごと自分の原稿に書きかえれば差し替え完了です。
> - `2026-09-10-kiechae-kiiro.md`(童話。差し替え済み:「消えちゃえ、黄色」)
> - `2026-09-15-tanuki-no-kasa.md`(民話)
> - `2026-09-21-kaisatsu.md`(ショートショート、コメディ)
> - `2026-09-28-ai-no-hirune.md`(AI)
> - `2026-10-01-kanpai.md`(コメディ)
>
> ファイル名を変えたいときは、編集画面の上にあるファイル名の欄を書きかえます(作品のURLも変わります)。
> 仮の作品をおすすめに入れているので、ファイル名を変えたり削除したりしたら、[おすすめ](#おすすめ作品)も直してください。

### 削除する

1. `works` フォルダで、削除したい作品ファイルを開きます。
2. 右上の **「…」(三点)メニュー → 「Delete file」** を押します。
3. **「Commit changes...」→「Commit changes」** を押します。

## 6. タグを追加・変更する

タグは **`settings/tags.txt`** の1ファイルにまとまっています。

```
童話:眠れない夜の、子どもにも大人にも。
民話:今日もお疲れさま。そんなあなたに、ひとつ。
```

- 1行に1つ、**`タグ名:説明文`** の形で書きます(コロンは全角でも半角でも可)。
- **追加**:いちばん下に1行足すだけです。トップページの雲も自動で増えます。
- **説明文の変更**:コロンの右側を書きかえます。説明文は、タグで絞り込んだときに書庫の上に出ます。
- **タグ名の変更**:ここを変えたら、そのタグを使っている作品ファイルの `タグ:` も同じ名前に直してください。
- `#` で始まる行はメモです(サイトには出ません)。

編集のしかたは作品と同じです(ファイルを開いて鉛筆マーク → 書きかえ → Commit changes)。

## 7. メニュー・おすすめ・お知らせを書きかえる

左側のカードの文章は `index.html` に書いてあります。鉛筆マークで開き、日本語の部分を書きかえます。
`<p>` と `</p>` のような記号(タグ)は消さないように、その間の文章だけを書きかえてください。

### 案内・自己紹介

`<!-- ===== 左列:メニュー・おすすめ ===== -->` の下にあります。
「個人が運営する短編小説サイトです。」の一文は、案内カードの最初にあります。

### おすすめ作品

```html
<li data-recommend="2026-09-10-kiechae-kiiro"></li>
```

`data-recommend="…"` の中に、作品ファイル名(`.md` / `.txt` を除いた部分)を書きます。
作品名と紹介文は自動で表示されます。おすすめを増やすときは、この行をコピーして1行増やします。

### お知らせ・更新情報

```html
<li><time datetime="2026-10-02">2026.10.02</time>サイトをひらきました。のんびり更新していきます。</li>
```

この行をコピーして、日付と文章を書きかえると、お知らせが増えます。
その下の「最近の更新」は、新しい作品3本が自動で表示されます。

### アイキャッチ(雲の上の文章)

`<p class="eyecatch__text" …>` の中の文章です。`<br class="sp-only">` はスマホのときだけ改行する印です。

## 8. 色を変える

`css/style.css` の先頭、「色の設定」にすべての色がまとまっています。

```css
--bg-top: #eaf6fb;     /* 背景の上のほう(淡い青) */
--accent: #2f7fa3;     /* リンクやボタンの文字(青) */
```

`#` から始まる6けたの値(色コード)を書きかえると、サイト全体の色が変わります。
すぐ下の `[data-theme="dark"]` の部分は、ダークモードのときの色です。

## 9. 検索エンジンに載せる(noindex の外し方)

いまは、Google などの検索結果に **出ない** 設定になっています。
検索に出したくなったら、`index.html` の上のほうにある次の1行を **削除** してください。

```html
<meta name="robots" content="noindex, nofollow">
```

(その上の、説明のコメント行もいっしょに消してかまいません)

## 10. 警告が出たとき

作品ファイルやタグの書き方に問題があると、サイトの右下に黄色い **「作者向けのお知らせ」** が出ます。
(ブラウザの開発者ツールの「コンソール」にも同じ内容が出ます)

例:

- `works/2026-10-15-tsuki.md タグ「ファンタジー」は settings/tags.txt にありません。`
  → 作品のタグ名の字をまちがえているか、`settings/tags.txt` への追加が必要です。
- `必須の項目「作品名」がありません。`
  → `作品名:` の行を書き忘れていないか、字がちがっていないか確認します。
- `項目と本文を分ける水平線「---」の行が見つかりません。`
  → 項目の下に `---` だけの行を入れます。
- `「公開日」の「…」が日付として読めません。`
  → `2026-10-15` の形で書きます。

どのファイルの、どこがおかしいかが表示されるので、そのファイルを直して保存すれば消えます。
問題がなければ、このお知らせは表示されません。

## (参考)自分のパソコンで表示を確かめる

必要なときだけで大丈夫です。ファイルをダブルクリックで開くだけでは作品が読みこまれないため、簡単なサーバーを使います。

```sh
node tools/build-index.js     # 作品一覧を作る
python3 -m http.server 8000   # http://localhost:8000/ を開く
```
